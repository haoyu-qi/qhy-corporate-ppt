# qhy-corporate-ppt：企业模板驱动的 PPT Skill 框架

设计稿 v0.1 · 2026-10-20

状态：框架设计。维护者已报告存在跑通的内部方案，但实现代码、企业模板与验证样例尚未纳入本仓库。本仓库目前不提供可安装 Skill 或执行引擎。参考项目的能力描述来自文档与源码阅读，不代表已完成运行对比。

## 1. 定位与交付承诺

**使用企业提供的原始 PPT 模板，完成内容生成和更新，保留品牌资产与模板结构，让业务人员在 PowerPoint 中继续修改，并给出具体的验收证据。**

暂定名称 `qhy-corporate-ppt`。独立于面向多风格演示的 `qhy-ppt`，避免两者对“模板”的理解冲突。

优先服务三类实际工作：固定模板的月报/季度汇报；沿用公司模板的项目方案；已有汇报材料的周期更新。是否存在足够的外部需求和付费意愿仍需真实用户验证，本框架不把个人成功案例推导为市场结论。

首版承诺限定在经过建档和测试的企业模板、对象类型、字体环境和目标客户端内。模板保真包括视觉、结构、编辑行为三个维度，不能只凭截图相似度判定。

## 2. 已有能力与参考结论

| 来源 | 本次确认的依据 | 可吸收能力 | 新框架的处理 |
|---|---|---|---|
| 本地 qhy-ppt | SKILL.md、export-pptx.mjs、html-deck-to-pptx README 与导出实现 | 逐页 brief、内容映射、容量选版、素材管理、导出报告 | 复用内容组织思想；企业模板任务不默认选择内置主题，也不默认每页生成四个方案 |
| 本地 qhy-ppt 的企业视觉模式 | 企业模板参考文档 | 企业视觉样式的经验 | 当前是 HTML 模板；不能据此声称已保留原 PPTX 母版结构 |
| 本地 qhy-image-to-ppt | SKILL.md、audit_pptx.py | 原生文字/形状/表格与图片分层，Logo 原素材保留，底图重影检查，对象盘点 | 复用对象分类与验收原则；对象数量检查不能证明完整可编辑或视觉保真 |
| PPT Master | 模板架构、结构接口、Edit Native PPTX 工作流 | Brand / Style / Layout / Deck 分工，母版/版式/占位符契约，原文件编辑、未改对象恢复、导出回读 | 作为对照基线；实际依赖或移植实现前另做兼容性测试与许可证核对 |

本次查到的 PPT Master 已经具有企业模板和原生结构相关路线，不能将其概括为“仅能做初级演示”。新的价值主张应落在企业规则的明确表达、稳定执行、可验证交付以及周期改稿成本上。现有 HTML 导出也能生成可编辑对象，不能把 HTML 路线一概等同于整页截图。

## 3. 四个任务入口

| 入口 | 用户说法 | 核心输入 | 主要输出 |
|---|---|---|---|
| 模板建档 `onboard` | 把这套公司模板整理成以后能重复使用的模板 | PPTX；后续可支持 POTX；可选品牌规范/官方 Logo | 带来源与版本的企业模板包、版式目录、支持边界 |
| 按模板生成 `generate` | 用公司模板，把这些材料做成季度汇报 | 已建档模板或原 PPTX、业务材料 | 原生 PPTX、预览、检查报告 |
| 局部更新 `revise` | 只改第三页的数据，其他页保持 | 当前交付版 PPTX、修改要求 | 新版本 PPTX、变化清单与受影响页报告 |
| 一致性检查 `audit` | 检查这份 PPT 是否符合公司模板 | 待检查 PPTX、对应模板包 | 按页/对象定位的问题；有修复要求时再生成修复版 |

没有原生模板、只有截图时，可提供视觉重建，但明确该模式不能恢复未知母版和原始继承结构。模板建档与日常使用分开，模板版本和环境未变时不反复建档。

## 4. 总体流程与模块边界

```text
公司原始模板 + 品牌规范                 业务材料 + 本次任务
             │                                │
      模板解析与建档                       内容规划
             │                                │
   企业模板包：原文件/规则/版式 ──────→ 页面与槽位映射
                                              │
                                    受约束的修改计划
                                              │
                                     原生 PPTX 执行器
                                              │
                             结构检查 + 最终文件渲染 + 编辑验证
                                              │
                                 PPTX + 预览 + 检查报告
```

Agent 负责理解业务材料、选择已登记版式、组织内容和处理语义。确定性程序负责对象定位、资源复制、PPTX 修改和规则检查。模型不通过记忆坐标或反复提示“不要改 Logo”来承担保真责任。

### A. 模板解析：先区分素材种类

- 母版型：主要依赖 Master / Layout / Placeholder，解析并保留继承关系。
- 示例页型：大量内容在普通幻灯片对象内，保留示例页作为原型，不强行转成母版型。
- 混合型：同时记录继承对象与页面本地对象；支持一份文件有多个母版。
- 纯图片模板：登记为视觉参考或受限模板，不标成全原生模板。

提取画布、母版/版式关系、占位符类型及索引、有效字体/字号/颜色、页脚、Logo 和安全区。样式解析必须包含主题、继承和局部覆盖；仅扫描显式 RGB 或字号不足以判断一致性。

每条规则记录 `source`、`confidence` 和 `status`，区分企业明确规范、从模板观察到的样式、待确认推断。模板中不一致的历史样式不自动升格成公司标准；影响生成的冲突集中列出。

### B. 企业模板包：让规则可执行

模板包至少包含：

1. **原始依据**：原 PPTX 及哈希、模板版本、来源说明。
2. **品牌规则**：主题色/辅助色/语义色、中文与西文字体、字号角色、Logo 资产及允许变体。
3. **版式目录**：每个原型对应的源页、Master、Layout、槽位、容量、适用内容关系。
4. **修改权限**：每个对象或角色哪些属性可变、哪些需保留。
5. **支持边界**：可编辑对象、可保留但暂不支持改写的对象、字体与客户端要求。
6. **基准证据**：代表性模板页渲染图、测试场景和检查结果。

字号一致性指相同语义角色遵循同一套字号规则，允许模板定义封面、标题、正文、注释的差异；色调一致性也不等于全文件只能有一种颜色。照片、业务截图和经允许的合作方 Logo 有明确例外范围。

### C. 对象修改契约

| 对象类别 | 允许操作 | 默认保留 |
|---|---|---|
| 品牌固定资产 | 仅按已确认品牌规范选择现有变体 | 原始素材、比例、位置规则、安全区、可见性 |
| 内容槽位 | 改文字、数字或绑定数据 | 槽位角色、字体、字号级别、颜色、边界 |
| 图片槽位 | 替换图片，按规则裁切 | 画框、纵横比策略、层级 |
| 可重复组件 | 增减经许可的卡片/行/列，必要时分页 | 组件样式、最小间距、数量与尺寸范围 |
| 批准的自由区域 | 添加支持的原生对象 | 公司色板、字体、网格、安全区 |
| 暂不支持编辑的原生对象 | 保留；确有修改需求时暴露限制 | 原对象及依赖，不自动降成截图 |

这里的“锁定”是生成过程的约束，不代表 PowerPoint 内的权限保护。位于母版的 Logo 通常在母版视图维护；普通业务文字应在页面内直接编辑。

### D. 内容与版式匹配

输入材料先形成逐页内容计划，保留事实来源、数字、单位与限定语。模板示例中的旧数字和文案不作为新材料的事实来源。

先按表达关系匹配页型：对比、进度、指标、过程、结论、表格；再核对内容容量。文本承载不下时，优先选择容量更合适的现有版式、拆页，或在用户允许的摘要范围内改写。字号只能在模板允许范围调整，不用无限缩字掩盖容量问题。固定页数与完整保留内容冲突时给出具体冲突位置。

### E. 原生执行器

优先接入维护者已经跑通的实现，通过统一接口暴露能力，而不是在未检查代码前替换技术栈。

执行优先级：保留原对象 → 修改明确允许的属性 → 复制现有页/组件 → 在允许区域新建支持的原生对象。只有选择了重建模式的部分才执行重建。

接口草案，均为设计约定，尚无可执行脚本：

```text
inspect(source) -> template_inventory
compile_rules(inventory, brand_rules) -> template_contract
plan(contract, content, request) -> mutation_plan
apply(source, contract, mutation_plan) -> output.pptx + change_receipt
validate(source, output, contract, mutation_plan, render_environment) -> report
```

每次输出新文件。修改对象使用源文件指纹、页标识、对象标识与原型映射定位，不能只凭可重复的对象名称；原文件改变后重新绑定，旧映射不可直接套用。

复制页/图表需处理其资源关系、数据工作簿、备注、连接线与跳转。共享对象发生局部修改时创建独立资源，防止只改一页却影响其他页；模板主题/母版变化需要显式声明影响范围。实现无法可靠保留的依赖须在生成前标记。

第二轮改稿以用户最新 PPTX 为输入，检查其与上次输出的差异，保留人工修改，不能从旧内容计划覆盖重生成整份文件。

### F. 验收器

验收针对最终 PPTX，而非中间 HTML/SVG。结果分别为 `pass`、`fail`、`not_run`，未运行不能算通过。

| 维度 | 检查内容 | 证据 |
|---|---|---|
| 文件结构 | 引用无缺失，母版/版式绑定、占位符与画布符合契约 | 包结构与引用检查报告 |
| 品牌资产 | Logo 素材、比例、位置、安全区、可见性符合规则 | 素材哈希或批准变体映射、几何检查、渲染 |
| 字体字号 | 有效样式与角色规则一致，字体可用，无未经允许的替换 | 样式继承解析、字体清单、客户端记录 |
| 色彩 | 主题色绑定和有效颜色正确，例外有范围 | 按对象/角色的色彩报告 |
| 可编辑性 | 文字可改；表格可改单元格；图表可改数据；形状可调整 | 语义对象与原生对象映射、代表性编辑测试 |
| 内容 | 数字/单位/来源正确，无旧模板内容遗漏、正文截断 | 内容回读与来源映射 |
| 视觉 | 无溢出、遮挡、错误换行、素材失真和底图重影 | 从最终 PPTX 渲染的逐页预览与检查记录 |
| 局部更新 | 变化在允许范围内，共享依赖与其他页未受意外影响 | 修改回执、对象/资源差异、受影响页对比 |

Logo 哈希相同只能证明素材未换，不能证明它没有被遮住或拉伸。图表存在也不能证明数据已同步更新，需核对图表缓存与工作簿。仅有一张 SVG 图片不能宣称图中每个组件可原生编辑。

不以“可编辑对象数量占比”充当唯一质量指标。分别统计需要编辑的业务文字覆盖、要求原生的表格/图表覆盖、固定品牌对象符合情况及未解决缺陷。首版目标为：约定必须编辑的业务内容全部满足契约，品牌硬规则无违规，无未解决的严重溢出；这些是验收目标，不是当前实测成绩。

模板基准与成品内容不同，不能用整页像素差当成失败依据。对比固定区域与未修改区域，结合结构检查和最终渲染判断。跨客户端差异记录操作系统、字体、应用与版本；未在 PowerPoint/WPS 实测不声称兼容已验证。

## 5. 数据契约示例

以下为示意值，不代表用户公司的规范。首版应先用一个模板验证字段必要性再扩展。

```yaml
schema_version: 1
template_id: sample-corporate-report
template_version: 1.0.0
source:
  path: source.pptx
  sha256: "<source-file-sha256>"
rules:
  typography:
    body:
      east_asian_font: "<approved-font>"
      allowed_sizes_pt: [18, 20]
      origin: supplied-brand-guide
  logo:
    asset: assets/logo.png
    asset_sha256: "<approved-asset-sha256>"
    preserve_aspect_ratio: true
prototypes:
  - id: two-column-comparison
    source_slide: 6
    layout_ref: "<resolved-layout-part>"
    slots:
      - id: title
        source_shape_id: 12
        role: slide-title
        editable_properties: [text]
        overflow: choose-another-layout-or-split
```

单次任务另存 `content_plan.json`、`mutation_plan.json` 与 `change_receipt.json`，避免把本次业务数据写入可复用模板规则。修改回执记录页/对象、操作、前后摘要及关联检查结果。

## 6. Skill 的组织方式

建议开发时采用以下结构。本轮只交付设计稿，不创建无实现的脚本或安装空壳 Skill。

```text
qhy-corporate-ppt/
├── SKILL.md                    触发条件、路由、核心约束、交付规则
├── references/
│   ├── onboarding.md           模板识别、规则证据、版式建档
│   ├── generation.md           内容规划、版式匹配、生成流程
│   ├── revision.md             局部更新与人工修改保护
│   ├── validation.md           检查定义、严重级别与客户端证据
│   └── contracts.md            模板/内容/修改/报告数据契约
└── scripts/                    在接入已有实现后按实际职责创建
```

企业模板和业务内容放在用户指定的本地项目/模板库，不默认进入公开 Skill 仓库。公开示例使用合成或经授权素材。任务不要求远端服务时，执行器使用本地资源；模型服务的数据处理边界单独按实际运行环境说明。

入口描述草案：

> 基于用户提供的企业 PPTX 模板生成或更新演示文稿，保留品牌 Logo、母版与版式关系、字体字号及颜色规则，并检查最终文件的原生可编辑性和模板一致性。用于公司模板填充、周期汇报、指定页面改稿及模板符合性检查。

入口主体只保留以下决策规则：识别任务 → 检查输入与模板版本 → 加载对应流程 → 明确允许修改的范围 → 调用可用执行器 → 检查最终 PPTX → 交付文件与未解决限制。详细字段和特殊对象处理放到 references，避免入口成为巨型手册。

## 7. 首版实施顺序

### 阶段一：把已有成功案例变成可复现基线

收集维护者跑通方案的代码/命令、原始模板、输入材料和最终 PPTX。先选一套企业模板，覆盖封面、章节、单栏、双栏、图文、表格/图表等实际存在的页型，不为凑页型强造版式。

拆出真实工作中必需的规则与偶然实现选择；固定输入、模板版本与环境，复现一次，并记录仍需人工处理的部分。优先验证 Logo、角色字号、颜色、可编辑性以及未修改页是否稳定。

### 阶段二：封装最小可用流程

完成四个入口中共用的解析、对象映射、执行回执和验收。日常生成流程仅支持已经验证的对象类型。首先解决文字、图片、原生表格，以及确实需要改数据的常用图表；动画和复杂对象保留原状，暂不扩大生成范围。

### 阶段三：验证泛化和周期改稿

加入母版型、示例页型、混合型三种模板，验证长标题、中文字体缺失、多母版、共享图表、拆页和用户手改后的第二轮更新。按实际交付场景选择 PowerPoint/WPS 客户端矩阵。

积累失败样例后再决定扩展 POTX、复杂图表、跨模板迁移和更多布局；不把支持任意企业模板作为首版宣传。

## 8. 必须覆盖的行为验证场景

| 场景 | 期望结果 |
|---|---|
| 标题变长，超出当前槽位 | 提出/执行允许的换版或拆页，不突破最小字号 |
| 同一 Logo 在母版、版式、页面不同位置出现 | 按归属和可见性核对，不误删为重复素材 |
| 模板未指定某个对象的显式颜色/字体 | 正确解析继承值，不把缺省值误判为不一致 |
| 公司字体未安装 | 标明未满足环境；有预先批准替代规则才替换并复验 |
| 只更新第三页数据 | 修改范围内的缓存/工作簿同步，其他页无意外变化 |
| 同一原型页复制两次后只改其中一页 | 两页独立更新，共享依赖按需要隔离 |
| 用户手工改完第一页再要求改第五页 | 以最新文件为基线，第一页人工修改保留 |
| 复杂 SmartArt 不在可编辑能力范围 | 原样保留并说明限制，不伪装成可编辑重建 |
| 只有整页图片的“公司模板” | 识别为受限输入，不报告原生模板继承通过 |
| 交付文件保存并重新打开 | 目标客户端无修复提示，代表性文字/表格/图表仍可修改 |

## 9. 验证用户价值的方法

先请真实使用公司模板的人完成一次典型任务，记录生成后还需要修什么。重点衡量修复时间、违规对象数量、成功完成第二轮改稿的情况；对比原有手工流程与现有工具在同一模板、同一材料上的结果。

对外展示建议用同一份材料的三组证据：成品视觉；PowerPoint 内修改文字/表格/图表的操作；模板规则检查与局部更新前后对照。先证明具体场景稳定可用，再决定是否扩大产品定位。
